# Incident Response / 安全与滥用事件响应

**版本：** 2026-10-24  
**适用：** 维护者、部署者、被误用的系统所有者

---

## 1. 立即止血

如果 host bridge / 输入 / 文件接口可能被滥用：

```text
停止 host bridge
停止 QEMU / VM
撤销/轮换 token
断开网络或限制到 127.0.0.1
关闭 --enable-input
删除/隔离可疑公网映射
保留日志（不要先删）
```

## 2. 判断范围

```text
哪个版本/commit
哪个 device_id
是否涉及 host://fs / display / input
是否有真实个人信息/凭证
是否有未授权第三方
是否仍在活动
```

## 3. 保留证据

```text
audit JSONL
系统日志
网络连接记录
相关截图/文件 hash
时间线
```

不要把含 token/个人信息的原始日志直接发到公开 Issue。

## 4. 通报

```text
如果是本项目漏洞：走私密 Security Advisory
如果是你的部署被入侵：按当地法律/合同通知相关方
如果涉及人身安全：联系紧急服务
```

## 5. 修复

```text
最小权限
默认拒绝
轮换密钥
更新依赖
增加审计/告警
限制 host 绑定
关闭不必要设备
```

## 6. 复盘

```text
根因
影响
检测为何失败
修复验证
需要更新的文档/测试
是否发布安全公告
```

## 7. 不要做

```text
不要为了掩盖而删除审计
不要继续使用已泄露 token
不要把责任推给“AI 自己决定的”
不要公开未修复漏洞的利用细节
```

## 8. 法律

如需通知执法/监管/数据主体，请按当地法律和律师建议执行。  
本文不是法律意见。
